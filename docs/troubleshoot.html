ClipSync relies on mDNS / Zeroconf (UDP Port 5353) for discovery and KCP (UDP Port 9999) for encrypted payload streaming. If devices do not appear in the Devices tab:

A. Allow UDP Ports in OS Firewall:

Linux (UFW Firewall)
$sudo ufw allow 9999/udp && sudo ufw allow 5353/udp $sudo ufw reload
Windows (PowerShell as Administrator)
PS>New-NetFirewallRule -DisplayName "ClipSync UDP Ports" -Direction Inbound -LocalPort 9999,5353 -Protocol UDP -Action Allow
macOS
Open System Settings > Network > Firewall and verify incoming socket connections are permitted for ClipSync.

B. Check Wi-Fi Router "AP Isolation" / "Client Isolation":

Many guest networks and public Wi-Fi access points turn on AP Isolation, preventing wireless devices on the same router from direct peer communication.

Fix: Connect both devices to your primary Wi-Fi network and ensure AP Isolation is disabled in router admin settings.

On Linux, ClipSync interfaces with system clipboard layers via standard display server tools. If copied text on Linux does not trigger automatic sync:

Step 1: Identify your display session

Terminal
$echo $XDG_SESSION_TYPE

Step 2: Install corresponding tool

  • If session is wayland:
    Wayland Tool
    $sudo apt install wl-clipboard # Ubuntu/Debian $sudo dnf install wl-clipboard # Fedora $sudo pacman -S wl-clipboard # Arch Linux
  • If session is x11:
    X11 Tool
    $sudo apt install xclip # Ubuntu/Debian $sudo dnf install xclip # Fedora $sudo pacman -S xclip # Arch Linux

Starting in Android 10 (API 29), the Android security model strictly prohibits background applications from modifying or reading system clipboard content without foreground user intent.

How ClipSync handles this on Android:

  1. When you copy text on your computer, ClipSync Android receives the encrypted packet and logs it in your History Feed.
  2. Open ClipSync and tap COPY on any clip card to place it in the active system clipboard.
  3. Paste into any app (WhatsApp, Gmail, Slack, Browser).

Keep Background Listening Alive:

To prevent Android OS from suspending UDP listeners when your phone screen turns off: Go to Settings > Apps > ClipSync > Battery > Set to "Unrestricted".

If you extracted the standalone clipsync-linux.tar.gz archive on a minimal Linux installation, verify that the graphical runtime libraries are present:

Debian / Ubuntu / Linux Mint
$sudo apt install -y libx11-dev libx11-xcb-dev libwayland-dev wayland-protocols libxkbcommon-dev libxkbcommon-x11-dev libvulkan-dev libegl-dev libgles2-mesa-dev libxcursor-dev libxi-dev libxrandr-dev libxinerama-dev libxxf86vm-dev libxfixes-dev libgtk-3-dev libayatana-appindicator3-dev
Fedora / CentOS / RHEL
$sudo dnf install -y libX11-devel libwayland-dev libxkbcommon-dev vulkan-headers libayatana-appindicator3-devel gtk3-devel

ClipSync enforces a single-instance lock to prevent multiple daemons from binding to UDP port 9999 simultaneously.

When you close the main window, ClipSync does not quit; it minimizes into your system tray so clipboard synchronization remains active in the background.

  • To restore the window: Click the ClipSync icon in your Windows Taskbar Tray, macOS Menu Bar, or Linux Notification Area.
  • To completely exit: Right-click the ClipSync tray icon and select Quit.
  • Force terminate if stuck (Linux/macOS): Run killall clipsync in terminal.
